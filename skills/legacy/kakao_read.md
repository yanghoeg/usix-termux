---
name: kakao_read
description: 카카오톡 알림을 백그라운드로 읽어 안 읽은 톡을 요약하고, 답장 가능한 알림에 인라인 답장한다
---

사용자가 "카톡 요약", "카톡 뭐 왔어", "카톡 확인" 같은 요청을 하면:

1. `notif_list` 도구에 `package`=`com.kakao.talk` 를 줘서 카톡 알림만 조회한다.
   (앱을 열지 않고 백그라운드로 읽으므로 화면 전환이 없다.)
2. 각 알림의 `title`(보낸 사람/방)과 `text`(메시지 내용)를 보낸 사람·핵심 내용 중심으로
   한국어로 짧게 요약한다. `key`·`postTime` 같은 내부 필드는 요약에 넣지 않는다.
3. 알림이 하나도 없으면 "안 읽은 카톡이 없다"고 한 줄로 답한다.

사용자가 "답장해줘", "OO라고 보내" 처럼 답장을 원하면 아래 순서를 그대로 따른다
(이 절차는 슬롯만 채우면 된다 — 대상과 보낼 문구만 정하면 나머지는 고정):

4. **먼저 `notif_list`(package=com.kakao.talk)를 다시 불러 최신 목록**을 받는다. 낡은 목록의
   `key` 는 이미 사라졌을 수 있으므로 답장 직전 항상 새로 읽는다.
5. 사용자가 사람 이름을 대면(예: "부인한테", "홍길동한테"), 그 이름을 각 알림의 `title` 과
   맞춰 대상 알림 하나를 고른다. 한 턴에는 한 대상에게만 보낸다.
6. 고른 알림의 `canReply` 가 `true` 인지 확인한다. `false` 면(서비스성 알림 등) 답장할 수
   없으니 "그 알림은 답장이 안 된다"고 한 줄로 알리고 `notif_reply` 를 부르지 않는다.
7. `notif_reply` 에 그 알림의 `key` 를 **결과값 글자 그대로** 넣는다(자르거나 지어내지 말 것 —
   key 는 `0|com.kakao.talk|2|...|...` 처럼 긴 문자열이며 일부만 넣으면 엉뚱한 곳에 가거나
   실패한다). `text` 에는 사용자가 준 문구를 그대로 넣는다.
8. 대상이 모호하면(이름이 여러 알림과 겹치거나 아무 이름도 없으면) 추측하지 말고 누구에게
   보낼지 사용자에게 되묻는다.
9. 전송이 확정되면 보낸 내용을 사용자에게 한 줄로 확인해준다. (도구가 오류를 돌려주면 보낸
   척하지 말고 실패 사실과 이유를 그대로 전한다.)

주의:
- 이 스킬은 **안 읽은 알림에 담긴 최근 메시지만** 읽는다. 이미 읽었거나 지워진 톡, 지난 대화
  전체 기록은 읽을 수 없다(그건 화면읽기나 root 가 필요).
- `canReply` 가 `false` 인 알림(서비스성 알림 등)에는 답장할 수 없다. 사용자에게 그 알림은
  답장이 안 된다고 한 줄로 알려준다.
- 알림 읽기·답장에는 companion 앱의 '알림 접근' 권한이 켜져 있어야 한다. 도구가 브리지
  무응답이라고 하면 사용자에게 권한을 켜달라고 한 줄로 안내한다.
